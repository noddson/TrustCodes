Optional context password

The creator can bind setup material to a context and then discard it. Both people re-enter it while using the TrustCode; it is never stored or exported.

What does the encrypted vault protect?

Saved entries are encrypted with AES-256-GCM. The key is derived from your passphrase with PBKDF2-HMAC-SHA256 and a random salt. This protects closed or locked data at rest. While unlocked, the page’s JavaScript can use the key and decrypted secrets; a compromised page, extension, browser profile, or device could expose them. Browser data may also be cleared, so retain setup backups.

How does a one-way proof work?

The verifier hashes the supplied phrase once and compares it with the stored anchor. After success, that phrase becomes the next anchor. Calculating the following phrase would require reversing SHA-256.

How is the context password handled?

At creation, PBKDF2-HMAC-SHA256 uses the context and an independent random salt for each device to wrap its secret, seed, or anchor. The creator’s input is then cleared. Setup codes and the encrypted vault retain only the salt and wrapped material. Both people re-enter the context while using the TrustCode. Even if both omit it or enter the same wrong value, their independently salted material does not match. Leaving context empty at creation preserves normal context-free behavior.
